> 本文收录 README 之外的机制说明：目录结构、三类数据文件格式、下载流程与任务语义、HTML 反查索引的查询行为。

## 二、游戏配置（`json/gamebanana.com.json`）

记录每个游戏：**英文名（key）+ 香蕉网 id + 中文名 + 下载路径**。

```json
{
  "Genshin Impact": {
    "id": 8552,
    "cn": "原神",
    "downloadPath": "/path/to/your/Mods/Genshin Impact/"
  }
}
```

内置示例游戏（id 为香蕉网权威 id）：

| 游戏 | 香蕉网 id | 中文名 |
| --- | --- | --- |
| Honkai Impact 3rd | 10349 | 崩坏 3 |
| Genshin Impact | 8552 | 原神 |
| Honkai Star Rail | 18366 | 星穹铁道 |
| Zenless Zone Zero | 19567 | 绝区零 |
| Wuthering Waves | 20357 | 鸣潮 |
| Arknights: Endfield | 21842 | 终末地 |

真实配置含本机路径，已被 `.gitignore` 忽略，不会上传；网页「设置 → 添加游戏」即可配置。

## 三、映射（`mapping/<游戏名>.json`）

映射决定下载路径怎么算：

```json
{
  "warehouses": { "characters": "角色", "weapons": "武器", "skins": "角色/.角色" },
  "roles": { "Sandrone": "桑多涅", "Varesa": "瓦雷莎" },
  "variants": { "桑多涅": "Sandrone", "danhenglunae": "Dan Heng Imbibitor Lunae" }
}
```

- `warehouses`：香蕉网大仓库 → 本地目录（`"角色/.角色"` 表示点开头的隐藏子目录）。
- `roles`：角色英文 → 中文，目录名写成 `英文 – 中文`。
- `variants`：搜索归一变体（中文/别名 → 规范英文）。

可在网页「设置 → 映射管理」手动添加：选游戏 → 选仓库 → 从香蕉网拉取角色列表 → 填中文名。

## 四、角色列表缓存（`json/role/<游戏名>.json`）

搜索页「按角色」与设置页「映射管理」共用同一份角色列表：

```json
{
  "gameId": 8552,
  "characters": [{ "name": "Aether", "url": "https://gamebanana.com/mods/cats/19510" }],
  "at": 1759
}
```

- `url` 是该角色的香蕉网分类页地址；「按角色」搜索取它的 `catId`，再抓该分类的**全量** mod。
- 角色列表来源：游戏根分类里匹配 `/character|skin/i` 的根 → 取其子分类；若子分类是容器分区（`Characters` / `Weapons`）则再下探一层取真角色。
- 旧格式（只有名字的字符串数组）读取时自动归一化，并在首次用到该游戏时重新抓取补网址（懒迁移）；本地手工添加、香蕉网上没有对应分类的角色，`url` 为空。

## 五、下载四步流程

输入 `https://gamebanana.com/mods/704164` 或纯数字 `704164`：

1. **生成 HTML**：拉取 GB ProfilePage 生成 `description.html`（作者/游戏/分类/文件 MD5/图片/gif），并计算下载路径：`下载根目录 / 仓库层(映射) / 角色层(英文 – 中文) / [作者] mod名`。
2. **查重归位**：全游戏根目录按文件名索引；已存在于其他文件夹 → 整个文件夹 `mv` 到规范路径（文件全部保留，HTML 覆盖）；残留的重复目录进根目录 `.trash`（可恢复）。
3. **整理阶段**：`.gbmd.part` 主文件与 part 都在 → 删 part，仅 part → 保留（断点续传）；文件名一律按 GB 原名保存（压缩包/图片/gif 都不重命名）。
4. **正式下载**：按 HTML 文件列表并发下载缺失文件（Range 断点续传、失败重试、停滞检测）；不改原始文件名，非法字符用空格替换。

### 下载内容与开关

- **压缩包**：GB `_aFiles` + 归档文件；关掉则第四步不入队压缩包，HTML 仍记录文件表。
- **预览图**：GB 原图 + 简介里的 gif；关掉则图片和 gif 都不下。gif 失败自动跳过（不强求）。
- `description.html` 始终生成（查重/反查依赖它，不提供关闭）。
- 下载时若 `.trash` 里有同名文件（含 `dup-归位-` 前缀目录），自动找回而非重新下载。
- 暂停/继续/终止/完成/导入追加都会写 `[task]` 日志（`server/server.log`，带时间戳）。

### 任务导入 = 纯追加

网页、`/api/task/import`、`/api/receive`、油猴、扩展**一律追加**，没有覆盖路径：

| 当前任务状态 | 导入行为 |
| --- | --- |
| 运行中 / 准备中 / 已暂停 | 追加到队列尾部，已有列表不清空（paused 会自动恢复下载） |
| 已完成 | 完成列表保留展示；新任务开始前清空旧批次 → 追加到空 |
| 已终止 | 终止即清空队列；之后导入 = 新建任务 |

看起来像「覆盖」的操作，实际都是「追加到空」；终止按钮是唯一清空队列的入口。

## 六、HTML 反查的查询行为

索引按游戏分文件存 `json/index/<游戏名>.jsonl`（旧版 `.json` 仍可读），每个文件含三块：

| 索引 | 内容 |
| --- | --- |
| GB 线上信息表 | hash → mod 名/作者/游戏/链接/GB 文件名 |
| 本地信息表 | hash → 本机实际下载目录/文件名 |
| HTML 原名表 | GB 原名（图片短名/压缩包名）→ mod |

查询行为：

- **本地表命中**（本机下载过）→ 显示 mod 信息 + 本机实际目录。
- **仅 GB 表命中**（线上有、本机没下）→ 显示线上信息 + 「下载此 mod」按钮。
- **HTML 原名表命中**（输入图片短名）→ 从全部 `description.html` 反查所属 mod。
- **离线目录搜索**：按 mod 名/作者模糊搜 GB 表，未下载的可一键下载。
- 输入**不必写后缀**：`69b46e18405cc` 与 `69b46e18405cc.jpg` 都能命中，大小写不敏感；压缩包名同理。

索引维护：启动自动加载三表；每次新下载写完 HTML 后自动增量并入；全量重建用设置页「重建索引」（只重建索引表，不补算内容 md5）。

存储后端、SQLite 实验与回退对比、内容 md5 不再回填的原因，见 [索引存储技术文档](索引存储技术文档.MD)。
