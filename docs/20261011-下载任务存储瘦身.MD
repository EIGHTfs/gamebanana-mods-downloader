## 一、修改目标

- **问题**：`json/download_task.json` 单文件存全部下载任务，万级条目后网页很卡
- **实测基线**（部署端，2026-10-11 04:5x）：

| 指标 | 实测值 |
|---|---|
| `json/download_task.json` | **12.7 MB** |
| `task.items`（按文件，非按 mod） | **12,782 条 / 8.23 MB（占 65%）** |
| `task.pendingMods` | 3,654 条 / 351 KB |
| `task.resultsMap`（按下标） | 12,896 键 / 2.94 MB |
| `resultsMap` 终态分布 | `ok:true` 100%、`skipped` 12,836、`exists` 12,711 |
| `saveTask()` 单次 | stringify **80 ms** + 写盘 **21 ms** ≈ **100 ms**（被 ~18 处调用，含每个文件状态变化） |
| `/api/task` 响应 | **10.8 MB**，0.11–0.15 s，**前端每 2 秒轮询**（≈5.4 MB/s） |
| 已发现的数据不一致 | `resultsMap` 键数 **12,896 > items 12,782**（114 个越界键） |

- **本阶段目标**（Step 1-2）：
  1. 每次落盘前清掉 `resultsMap` 中越界（下标 ≥ `items.length`）的键——它们无法映射到任何 item，只占体积
  2. `saveTask()` 由「同步全量写」改为「脏标记 + 合并写（≤500ms 一次）+ 临时文件 rename 原子替换」，关键节点立即落盘
- **成功标准**：
  - 写盘次数：下载进行中由「每文件状态变化一次」降到 **≤2 次/秒**
  - 单次写盘不再阻塞事件循环（异步化后主线程不再被 100ms 同步写占用）
  - 落盘文件始终是**完整 JSON**（原子替换：崩溃/断电不会留下半个文件）
  - 任务语义零变化：`items` / `resultsMap` / `pendingMods` 内容与顺序不变（越界键除外）

## 二、潜在问题分析

| 风险 | 可能性 | 影响 | 缓解 |
|---|---|---|---|
| 节流期间进程被杀 → 最后 ≤500ms 状态丢失 | 中 | 进度回退一小段 | 关键节点（批次开始/终止/暂停/恢复/重启恢复）与进程退出时强制 flush |
| 原子写失败（磁盘满/权限） | 低 | 该次落盘失败 | 失败只记日志不抛（保持原 `try/catch` 语义）；临时文件带 pid 后缀避免并发撞名 |
| 调用方依赖「saveTask 返回后文件已更新」 | 低 | 立即读文件的地方拿到旧内容 | 全量检索 saveTask 调用点：无「写完立即读」用法（落盘只供重启恢复） |
| 清越界键误删有效结果 | 低 | 结果丢失 | 越界键（下标 ≥ items.length）本就无法映射 item；删除前单测覆盖边界（空 items/空 resultsMap/全越界） |
| 定时器阻止进程退出 | 低 | 服务无法退出 | 定时器 `unref()` |
| 与自动更新/备份的交互 | 中 | 新临时文件被当成数据文件 | 临时文件写在同目录、rename 后即消失；`.tmp-<pid>` 不会被备份清单收录（清单由标记注释驱动） |

**边界条件**：① `items` 为空数组 ② `resultsMap` 为空/非对象 ③ 两者长度一致（无越界键）④ 500ms 内连续多次调用只落一次盘 ⑤ 落盘过程中再次调用（合并进下一次）⑥ 任务文件所在目录不存在（沿用 `ensureJsonDir`）

## 五、逐文件改动详情

### 5.1 `server/lib/download-task-store.js`（新增）

- `pruneStaleResults(task)` → 删除 `resultsMap` 中 `下标 < 0 或 ≥ items.length` 的键，返回删除数（`items` 非数组或 `resultsMap` 非对象时安全返回 0）
- `buildSnapshot(task)` → 旧 `saveTask` 的快照逻辑原样迁入：剥离 `activeItems[]._spT/_spLast`、`preparingItem` 只留 `{name,type}`；`task` 为 null 时返回 null
- `writeFileAtomic(filePath, text)` → 写 `<filePath>.tmp-<pid>` 后 `rename` 覆盖（同目录 rename 原子）
- `createTaskWriter({ filePath, ensureDir, throttleMs, buildText, log })` → 返回 `{ save(), flush(), stats() }`：
  - `save()`：置脏 + 若未排程则 `setTimeout(flush, throttleMs)`（`unref`）
  - `flush()`：取消排程 → 若脏则 `ensureDir()` + `writeFileAtomic()`；写失败只记日志
  - `stats()`：`{ writes, saves, coalesced }` 供测试与自检读取

### 5.2 `server/lib/downloader.js`

- 顶部 require 新模块；`saveTask()` 改为委托 `writer.save()`，新增 `flushTask()` 委托 `writer.flush()`
- 旧实现（全量同步 `writeFileSync`）**注释保留**在函数内，便于回退
- 关键节点追加 `flushTask()`：`startDownloadTask`（批次开始/追加后）、`stopTask`、`pauseTask`/`resumeTask`、`restorePendingTask`
- 进程退出兜底：`process.once("exit", flushTask)`（同步写，确保优雅退出不丢最后状态）
- 落盘前自动 `pruneStaleResults`（在 `buildSnapshot` 内调用，保证每次写盘都是干净的）
